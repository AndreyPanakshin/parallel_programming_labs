# Лабораторная работа №4: Параллельное перемножение матриц (CUDA)

## Описание файлов

| Файл | Назначение |
|------|------------|
| `gpu_matmul.cu` | Исходный код на CUDA. Реализует два ядра: базовое (глобальная память) и оптимизированное (разделяемая память с блоками 16×16). |
| `check_results.py` | Скрипт верификации. Сравнивает результат GPU-вычислений с эталоном NumPy. |
| `draw_graphs.py` | Генерация графиков: время выполнения, ускорение, сравнение памяти, производительность в GFLOPS. |
| `build.bat` | Скрипт сборки для Windows с проверкой наличия CUDA Toolkit. |
| `stats.csv` | Статистика экспериментов (размер, блок, тип памяти, время, операции, данные). |
| `matrix.txt` | Входной файл с двумя матрицами (генерируется автоматически). |
| `result.txt` | Результат умножения матриц на GPU. |

# Запуск программы

## Требования
```bash
# Ubuntu/Debian с NVIDIA GPU
sudo apt update
sudo apt install -y nvidia-cuda-toolkit python3 python3-pip
pip3 install numpy matplotlib

# Проверка установки CUDA
nvcc --version
```

## Сборка
- `make all`

## Запуск тестов
- `make run-all`

## Построение графиков
- `make graphs`

## Полное тестирование
- `make experiment`

# Процесс проверки
1. CUDA-программа умножает матрицы на GPU и сохраняет результат в result.txt
2. check_result.py считывает входные матрицы из matrix.txt
3. NumPy вычисляет эталонное произведение A × B на CPU
4. Выполняется сравнение результата CUDA с эталоном
5. Выводится максимальная погрешность и статус проверки (PASS при погрешности < 10⁻³)

# Выводы по Лабораторной работе №4(CUDA)
## Ключевые наблюдения:
1. **Эффективность распараллеливания на GPU**
   CUDA обеспечивает высокую производительность при умножении больших матриц (от 800×800 и выше). Архитектура GPU с массово-параллельными вычислениями позволяет достичь производительности ~125 GFLOPS на видеокарте GTX 1060 3GB.
2. **Оптимальная конфигурация блоков**
   Наилучшая производительность достигается при размере блока 32×32 потока, что обеспечивает максимальную загрузку потоковых мультипроцессоров архитектуры Pascal. Конфигурация 16×16 также показывает хорошие результаты и является более универсальной.
3. **Преимущества разделяемой памяти**
   Использование разделяемой (shared) памяти обеспечивает дополнительное ускорение на 7-10% по сравнению с глобальной памятью за счёт снижения количества обращений к медленной глобальной памяти GPU и улучшения локальности данных.
4. **Масштабируемость**
   Время выполнения растёт кубически с увеличением размера матрицы (O(n³)), что соответствует теоретической сложности алгоритма умножения матриц. Однако абсолютное время выполнения на GPU значительно меньше по сравнению с CPU-реализациями.
5. **Сравнение с MPI и OpenMP**
   CUDA демонстрирует значительно более высокую производительность (~125 GFLOPS) по сравнению с MPI (~1-2 GFLOPS), что объясняется специализированной архитектурой GPU, оптимизированной для выполнения однотипных операций над большими массивами данных.
6. **Резервы оптимизации**
   Достигнутая производительность составляет около 2.8% от теоретического максимума видеокарты (~4.4 TFLOPS), что указывает на наличие значительных резервов для дальнейшей оптимизации (использование тензорных ядер, более эффективное использование кэш-памяти, оптимизация доступа к памяти).
